# Сигнал — цифровой деканат (концепт)

Концепт личного кабинета студента для конкурса MGIMO AI Challenge 2026, номинация «Вайб-кодинг». Не официальный сервис вуза. Все люди, оценки и документы вымышлены.

## Идея
Деканат пишет первым. Студент открывает кабинет и сразу видит, что важно сегодня: перенос пары, близкий дедлайн, риск по дисциплине, готовую справку, скорую сессию. У каждой карточки есть строка «Почему я это вижу» и действие в одно касание.

## Сценарий проверки за 2 минуты
1. Войти как student2: на экране «Сегодня» перенос пары, дедлайн курсовой, риск по дисциплине, сессия.
2. «Расписание» → «Неделя»: переносы и отмена выделены.
3. «Учёба»: светофор по дисциплинам, допуск, даты экзаменов.
4. «Заявки»: заказать справку, увидеть статус «Подана».
5. Выйти, войти как dekanat: перевести заявку в «В работе», затем в «Готова».
6. Снова войти как student2: карточка и уведомление о готовой справке.
7. Войти как student1 и открыть адрес `#/req/3` (заявка другого студента): «Не найдено».

## Что есть
Вход и профиль, расписание на день и неделю с переносами, успеваемость и сессия, заявки со статусами, уведомления и объявления, страница сотрудника. Работает на экране от 360 px.

## Как устроено (простыми словами)
- Один файл `index.html`: разметка, стили и логика без сторонних библиотек и шрифтов.
- Данные демо хранятся в браузере (localStorage) и сохраняются после перезагрузки страницы.
- В коде лежат не пароли, а их хеши; сверка идёт по хешу. Ключей сторонних сервисов в проекте нет.
- Студент видит только свои заявки: запрос чужой заявки по адресу даёт «Не найдено». Раздел сотрудника закрыт для студентов.
- Логотип «Сигнал» собственный. Официальный логотип вуза не используется.

## Честные ограничения прототипа
- Сервера и общей базы нет: разделение данных и вход работают на стороне браузера. Это демонстрация логики, а не промышленная защита.
- Смена статуса сотрудником видна студенту в том же браузере.
- Следующий шаг: серверная часть (Flask или FastAPI, PostgreSQL), серверные сессии, хеши паролей на сервере.

## Как шла работа с ИИ
- Инструменты: Claude (Anthropic) — разбор задания, анализ публичных работ участников, проектирование экранов и правил, написание всего кода, тексты и демо-данные, автоматическая проверка сценариев.
- Этапы: 1) разбор задания и критериев; 2) исследование болей студентов и решений конкурентов; 3) выбор идеи «деканат пишет первым»; 4) спецификация экранов, правил и демо-данных (`SPEC.md`, `CLAUDE.md` — документы для ИИ-агента); 5) генерация кода; 6) автопроверка: синтаксис, вход под тремя аккаунтами, все экраны, чужая заявка, смена статуса.
- Ключевой промпт: «Собери рабочий кабинет студента одним файлом: вход, расписание с переносами, успеваемость, заявки со статусами, уведомления, страница сотрудника; главный экран — карточки по правилам из данных студента с объяснением „почему я это вижу“».
- Ошибки и решения: полный серверный вариант не уместился в срок — ИИ предложил урезать до одного файла и честно описать ограничения; хеширование через Web Crypto не работает при открытии файла с диска — заменено на собственную функцию.
- Вручную: постановка задачи, выбор идеи, публикация на GitHub Pages, проверка с телефона, отправка работы.
